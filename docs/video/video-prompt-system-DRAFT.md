## 0. Як це працює (одним абзацом)

Ти кидаєш промпт + **тему** + **посилання на відео конкурента** (або «знайди ідею сам»).
Claude робить діагностику → пропонує оригінальну ідею, назви й мініатюру → пише сценарій → озвучка Kokoro → звукові ефекти через ElevenLabs → вся анімація малюється кодом → рендер 1080p → на виході `.mp4`, мініатюра, `.srt` (для CC на YouTube), опис і теги.

## 3. Візуальний стиль: «Marker Whiteboard»

Взято з референсу (відео про Кольську надглибоку свердловину):

- **Фон:** тепла біла дошка `#FAF8F3`, ледь помітна текстура паперу. Без рамок і без UI.
- **Лінії:** товстий чорний контур маркером (3–6 px, нерівний край, легке тремтіння лінії, як від руки).
- **Заливка:** яскраві маркерні кольори, видно штрихи (не плоска заливка). Палітра: червоний `#E8322B`, помаранчевий `#F58A1F`, жовтий `#FFC93C`, синій `#1E88E5`, зелений `#3BA55C`, чорний `#1A1A1A`.
- **Заголовки:** рукописний жирний шрифт (тип Permanent Marker / Caveat Brush), чорний, з **червоним підкресленням** маркером.
- **Акценти:** жовті «промені» навколо ключових цифр або об'єктів (`= 180°C =`), червоні стрілки з підписом (`← 0.2%`).
- **Анімація (основа стилю):**
  1. об'єкт **промальовується контуром** (draw-on по шляху, 0.6–1.5 с);
  2. потім **зафарбовується штрихами** (scribble-fill, 0.5–1 с);
  3. текст пишеться по літерах, підкреслення «протягується»;
  4. жовті промені з'являються з легким «pop»;
  5. зміна сцени: очищення дошки (швидкий fade/стирання) або камера зсувається до вільного місця.
- **Композиція:** заголовок сцени зліва вгорі, головний об'єкт у центрі, допоміжний праворуч. **Максимум 3 головні об'єкти в кадрі.**
- **Темп:** нова дія на екрані кожні **3–6 с**, нова сцена кожні **10–25 с**. Статика довше 6 с заборонена.
- **Заборонено:** вотермарки (у референсі є лого golpo, у нас його нема), вшиті субтитри, фото, 3D, градієнти «як у корпоративних презентаціях».

## 4. Пайплайн (етапи)

### Етап 1. Діагностика конкурента
Інструменти: vidIQ (`video_stats`, `video_transcript`, `channel_videos`, `outliers`).
> YouTube не дає скачати відео на сервер, тому аналіз іде за транскриптом, статистикою, назвою та мініатюрою.

Вихід:
- **Цифри:** перегляди, вік відео, підписники каналу, множник над середнім каналу (outlier-score). Маленький канал з великим відео = сильний сигнал.
- **Упаковка:** назва (формула), мініатюра (які 3 об'єкти, чи повторює назву).
- **Структура:** хук перших 15–20 с, ставки, квести, де розв'язка.
- **Слабкі місця:** де «а потім… а потім», де відповідь видана зарано.
- **Прогалина:** що глядач захоче подивитися **наступним епізодом** і чого конкурент не зробив.

### Етап 2. Ідея (оригінальність, а не копія)
- 3 варіанти ідеї, кожен підходить під одну з формул:
  - **наступний епізод** (наприклад, «Титанік затонув» → «що знайшли всередині Титаніка»);
  - **перенесення формули** в іншу тему або спільноту;
  - **зміна формату** (реальні кадри → whiteboard-анімація);
  - **тренд + наша ніша**.
- Перевірка на копію: інша тема, інший кут або нова відповідь. Однакова назва + однаковий сюжет = відкинути.
- Якщо попереднє наше відео «вистрілило», ідея має продовжувати ту саму тему (не стрибати на випадкову).

### Етап 3. Упаковка (до сценарію!)
- **5 назв**, кожна з curiosity gap (питання / число / «що як…»), до 60 символів.
- **3 концепти мініатюри**, правила:
  - **правило 3 об'єктів** (група цифр або цін рахується як 1 об'єкт);
  - мініатюра **НЕ повторює назву** → «подвійний шок»: мініатюра дивує деталлю, назва пояснює;
  - текст на мініатюрі ≤ 3–4 слова;
  - той самий маркерний стиль, що й у відео.
- Рекомендація: 1 назва + 1 мініатюра з поясненням чому.

### Етап 4. Сценарій
Структура «відео = гра»:

| Блок | Час | Що робить |
|---|---|---|
| **Хук (tutorial)** | 0:00–0:20 | Ставки + проблема/обіцянка. Третій «шок» після мініатюри й назви. Без «привіт, підписуйтесь» |
| **Квест 1…N** | 0:20–7:15 | 4–6 квестів. Кожен — міні-проблема → поворот → часткова відповідь, що відкриває наступне питання |
| **Фінальний бос** | 7:15–8:00+ | Головна відповідь на назву. **Тільки тут**, не раніше |
| **Аутро** | 10–15 с | Міст до наступного відео (тема-продовження), CTA одним реченням |

Правила тексту:
- Між реченнями **«але / тому / бо / тож»**, а не «а потім». Кожен абзац перевіряється на «список подій».
- Кожні 60–90 с — нове питання або ставка («але є проблема…»).
- Головну відповідь не видавати до фіналу.
- Цифри й факти тільки перевірені; невідоме позначати `[MISSING]` і не вигадувати.
- Мова розмовна, короткі речення (≤ 20 слів), бо читає TTS.
- Сценарій одразу розмічений по сценах: `[SCENE 07 | visual: … | sfx: …]`.

### Етап 5. Озвучка
- Kokoro `am_puck` → `voice.wav` + таймінги по реченнях.
- Таймінги потрібні для синхронізації анімації та для генерації `.srt`.

### Етап 6. Візуал (код)
- Кожна сцена описана як JSON (об'єкти, шляхи, кольори, час появи), а рендерить код.
- Бібліотека перевикористовуваних об'єктів (глобус, стрілка, термометр, людина-стікмен, будинок тощо) росте з кожним відео → кожне наступне відео робиться швидше.
- Стек: `[ПИТАННЯ]`. Рекомендація: **Remotion (React + SVG)**, бо draw-on контурів і маркерна заливка там робляться природно, а рендер у 1080p стабільний. Альтернатива: Python (cairo/skia) + ffmpeg.

### Етап 7. Звук
- SFX з ElevenLabs: маркер по дошці, «pop», whoosh переходу, удар на ключову цифру, тиха напруга перед розв'язкою.
- Гучність: голос −14 LUFS (стандарт YouTube), SFX на 12–18 dB тихіше за голос.

### Етап 8. Рендер і пакет на вихід
`video.mp4` (1080p) · `thumbnail.png` (1280×720) · `captions.srt` · `title.txt` · `description.txt` (з таймкодами-розділами) · `tags.txt`

## 5. Контроль якості (перед видачею)
- [ ] Тривалість ≥ 8:00
- [ ] Немає вшитих субтитрів і вотермарок
- [ ] Хук ≤ 20 с, без привітань
- [ ] Відповідь на назву тільки у фіналі
- [ ] У сценарії нема блоків «а потім»
- [ ] Мініатюра ≠ назва, ≤ 3 об'єкти
- [ ] Немає статики > 6 с
- [ ] Ідея не дублює відео конкурента

## 6. Що з уроків свідомо НЕ йде в промпт
- «Розрив алгоритму», регулярність, «публікуй більше, навіть з −30–50% якості»: це **стратегія каналу**, а не правила генерації. Висновок для системи: генерація має бути швидкою і шаблонною, щоб ти міг публікувати часто.
- Ведення списку конкурентів: автор радить робити це **вручну**. Пропоную окремий файл `docs/video/competitors.md`, куди після кожного відео дописуються результати.

## 7. Бюджет кредитів ElevenLabs
- Тільки SFX, жодних картинок, відео чи голосу.
- Спочатку бібліотека з ~15–20 базових SFX: генеруються **один раз** і перевикористовуються.
- Нові SFX тільки під унікальні моменти, ліміт `[ПИТАННЯ: скільки на відео? пропоную ≤ 5]`.

## 8. Відкриті питання
1. **Мова відео** — англійська?
2. **Сценарій** — пише Claude за цією системою, чи ти даєш свій? (У повідомленні було «сценарій я сам генерю»: це про текст чи про озвучку?)
3. **Голос** — Kokoro `am_puck` («пик»), правильно?
4. **Озвучка** — Claude генерує Kokoro сам, чи ти озвучуєш і кидаєш файл? Можна обидва варіанти.
5. **FPS** — 30 чи 60?
6. **Фонова музика** — потрібна? Якщо так, звідки?
7. **Ніша / канал** — одна тематика (наука / «що як…») чи різні?
8. **Зупинка після етапу 3** — Claude показує ідею + назву + мініатюру й чекає «ок», чи робить усе до кінця без зупинок?
