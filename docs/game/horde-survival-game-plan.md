## 0. Рамка і технічна основа

**Що будуємо.** Оригінальну 2D-гру для браузера в жанрі horde survival / bullet heaven. Гравець тільки рухається, зброя атакує сама, монстри сунуть з усіх боків. З них падає XP, і кожен новий рівень дає вибір 1 з 3 апгрейдів. Мета забігу — протриматися якомога довше й побити свій рекорд часу.

**Принципи дизайну**

1. **Читабельність важливіша за видовище.** За пів секунди має бути видно, де я, де загроза і де нагорода.
2. **Кожна дія має відгук.** Влучання, вбивство, підбір і новий рівень завжди супроводжуються ефектом.
3. **Часті рішення.** Вибір апгрейду приблизно кожні 20–45 с.
4. **Тиск росте хвилями.** Піки чергуються з короткими паузами, щоб перепочити.
5. **Чесність.** Hitbox менший за спрайт, вороги повільніші за гравця, а після паузи є мить на реакцію.

**Технічна основа**

| Що | Рішення |
|---|---|
| Технології | HTML5 Canvas 2D + vanilla JavaScript (ES modules). Без фреймворків, бібліотек і збірки |
| Роздільність | Внутрішня 1920×1080: уся логіка й UI працюють у цих координатах |
| Масштабування | Canvas вписується у вікно зі збереженням 16:9, вільне місце заповнюють чорні смуги (letterbox). Масштаб — менше з двох чисел: ширина вікна / 1920 і висота вікна / 1080 |
| Миша | Координати кліку перераховуються у внутрішні 1920×1080 (для меню й карток) |
| Клавіатура | Читаємо фізичну клавішу (`event.code`), щоб WASD працювали і на українській розкладці |
| Спрайти | Source-спрайти персонажів і монстрів — PNG 182×182. Якщо файлу немає, використовуємо procedural placeholder того ж розміру |
| Розмір на екрані | Задається для кожного типу в `data/`, окремо від source (див. 4.6) |
| Колізії | Кола. Радіус завжди менший за намальований спрайт |
| Час | `dt` у секундах, не більше 0.05 с: після «підвисання» або перемикання вкладки ніщо не телепортується |
| Одиниці | Позиції — px світу, швидкості — px/с, cooldown — секунди, кути — радіани |
| Збереження | localStorage: рекорд і налаштування |
| Мова | Код: англійські імена й короткі коментарі. Тексти UI гри — англійською, поки не вирішимо інакше |

**Оригінальність**

- Усі назви (гри, зброї, ворогів, пасивок) власні й лежать у `data/`, тож їх можна замінити, не змінюючи логіку.
- Арт поки procedural placeholders, далі — власні спрайти. Звук власний або згенерований.
- Загальні механіки (автоатака, XP, вибір 1 з 3, скрині) є спільними для всього жанру. Реалізація, баланс і назви — наші.
- Перед публікацією перевірити, що назва гри не зайнята.

## 1. Core gameplay loop

```
 РУХ --> зброя б'є сама --> вороги гинуть --> XP-кристали --> збір
  ^                                                            |
  |                                                            v
 вороги сильнішають <-- білд сильнішає <-- LEVEL UP: 1 з 3 <---+
  |
  v
 смерть --> результат (час, рівень, вбивства, рекорд) --> "ще раз" (<= 3 с)
```

**Петлі різного масштабу**

| Масштаб | Що відбувається | Що відчуває гравець |
|---|---|---|
| 1–3 с | Маневри між ворогами, автоатаки, вороги «лопаються», падають кристали | Контроль і приємний хаос |
| 20–45 с | XP-бар заповнюється → Level Up → вибір | Очікування, потім нагорода |
| 1–3 хв | Elite → скриня, нова зброя, перші синергії | Відчуття, що «мій білд» росте |
| Забіг, 10–15 хв | Тиск росте, доки орда не переможе | Напруга і бажання зіграти ще раз |
| Між забігами (пізніше) | Рекорди, розблокування | Довга мотивація |

**Ритм забігу (цілі для балансу)**

| Час | Що має статися |
|---|---|
| 0:10–0:20 | Перший Level Up |
| 1:30 | Перший elite і перша скриня |
| Кожні ~60–90 с | Подія: elite, swarm або ring |
| 3–5 хв | 2–3 види зброї, білд має свій «характер» |
| 10:00 | Пік прототипу. Гравець приблизно на 20 рівні, тож білд ще не зібраний повністю (у прототипі ~40 можливих апгрейдів) |
| 10:00+ | Складність росте без кінця, доки гравець не впаде |

**Стани гри**

| Стан | Що відбувається | Куди можна перейти |
|---|---|---|
| `TITLE` | Назва, рекорд, «Press Enter» | → `PLAYING` |
| `PLAYING` | Гра і таймер забігу йдуть | → `PAUSED`, `LEVEL_UP`, `CHEST`, `GAME_OVER` |
| `PAUSED` | Світ заморожений, меню паузи | → `PLAYING`, `TITLE` |
| `LEVEL_UP` | Світ заморожений, 3 картки | → `PLAYING` (або знову `LEVEL_UP`, якщо в черзі ще є рівні) |
| `CHEST` | Світ заморожений, скриня відкривається | → `PLAYING` |
| `GAME_OVER` | Статистика забігу | → `PLAYING` (Retry), `TITLE` (Menu) |

Таймер забігу йде лише в `PLAYING`.

**Керування.** WASD або стрілки — рух. Esc або P — пауза. 1/2/3 або миша — вибір апгрейду. Enter — підтвердити. R — рестарт на екрані Game Over. Backtick (`) — debug, працює тільки коли `DEBUG = true`. Коли вкладка втрачає фокус, гра сама стає на паузу.

## 2. Перший прототип

**Мета прототипу:** перевірити, що петля «рух → вбивства → XP → вибір → сильніший білд → складніше» затягує. Без справжнього арту, звуку й мета-прогресії.

| Входить | Не входить (після прототипу) |
|---|---|
| Canvas 1920×1080, 16:9, letterbox | Еволюції зброї |
| Рух, камера, безкінечний фон | Бос, вороги, що стріляють або роблять ривок |
| 4 види зброї (1 стартова + 3 відкриваються), по 5 рівнів | Звук і музика |
| 6 пасивок по 5 рівнів, слоти 4 + 4 | Справжній арт і анімації |
| 3 типи ворогів + elite-варіант | Touch-керування, геймпад |
| XP-кристали трьох номіналів, магнітний підбір | Мета-прогресія (валюта, розблокування) |
| Level Up: 3 картки + черга рівнів | Кілька карт і персонажів |
| Хвилі за таймлайном + події swarm і ring | Налаштування, fullscreen |
| Скрині з elites (+1 рівень предмету або лікування) | Object pooling (якщо не знадобиться раніше) |
| Juice: hit flash, knockback, числа урону, частинки, тряска | |
| HUD, Title, Pause, Game Over, рекорд у localStorage | |
| Debug: hitbox-и, FPS, лічильники, чит-клавіші | |

**Definition of Done**

- Гра запускається в браузері через локальний сервер, без встановлення залежностей.
- 16:9 без розтягування при будь-якому розмірі вікна.
- 10+ хвилин гри без помітних просідань. Ціль — ~60 FPS при 300 ворогах на звичайному ноутбуці, перевіряємо debug-лічильником.
- Перший Level Up не пізніше 20 с, далі приблизно кожні 20–45 с.
- Від смерті до нового забігу не більше 3 с.
- Усі числа балансу є тільки в `config.js` і `data/`.
- Жодних чужих назв, арту чи звуків.

**Правила, щоб код годився для туторіалу для початківців**

- Один файл — одна відповідальність і один клас. Бажано до ~200 рядків.
- Дані окремо від логіки: баланс правимо в `data/`, а не в класах.
- Усі сутності мають однаковий інтерфейс: `update(dt, game)` і `draw(ctx, camera)`. Знищений об'єкт отримує `dead = true` і прибирається в кінці кадру.
- Жодних глобальних змінних, крім констант з `config.js`. До світу звертаємося через `game`, який передається в `update`.
- Увесь урон проходить через один метод ворога `takeDamage()`, тому фідбек однаковий для всієї зброї.
- Жодних «магічних чисел» у логіці. Коментарі пояснюють, чому код такий, а не переказують, що він робить.
- `Game.js` лише координує: викликає системи в правильному порядку, а власної ігрової логіки не має.

**Порядок кадру в `Game.js`** (update виконується тільки в стані `PLAYING`)

1. Input → рух гравця.
2. Spawner: таймер забігу, нові вороги, події.
3. Вороги: рух до гравця, розштовхування, затухання knockback.
4. Зброя: cooldown-и, постріли, орбіти, аура, хвилі.
5. Снаряди: рух, час життя.
6. Колізії: снаряди й зони урону з ворогами, вороги з гравцем, гравець з кристалами і скринями.
7. Смерті ворогів → кристали, скрині, частинки, лічильник вбивств.
8. Кристали (магніт), ефекти, тряска камери.
9. Прибрати `dead`. Перевірити: Level Up → `LEVEL_UP`, HP ≤ 0 → `GAME_OVER`.

**Шари малювання (знизу вгору):** фон → аура (на «землі») → тіні → кристали і скрині → вороги (відсортовані за y) → гравець (завжди поверх ворогів) → снаряди, осколки, хвилі → частинки → числа урону → HUD → оверлеї.

**Запуск.** Браузери не завантажують ES modules, якщо відкрити файл напряму (`file://`), тому гру запускаємо через локальний сервер: розширення Live Server у VS Code, `npx serve` або `python3 -m http.server`. Покрокова інструкція буде в README гри.

## 4. Сутності

### 4.1 Player

| Поле | Старт | Навіщо |
|---|---|---|
| `hp` / `maxHp` | 100 / 100 | HP-бар під спрайтом |
| `speed` | 300 px/с | Вектор руху нормалізується, тож по діагоналі не швидше, ніж прямо |
| `level` / `xp` / `xpToNext` | 1 / 0 / 5 | Формула — у розділі 5 |
| `pickupRadius` | 110 px | З цієї відстані кристали летять до гравця. Росте з Magnet |
| `radius` (hurtbox) | 28 px | Для спрайта 128 px на екрані |
| `invulnTimer` | 0.5 с після удару | Мигання; не дає миттєво загинути в натовпі |
| `facing` | Останній напрямок руху | Віддзеркалення спрайта, а згодом і зброя, що б'є в напрямку руху |
| `weapons` / `passives` | [Seeker Bolt Lv1] / [] | Слоти 4 + 4 |
| `stats` | Множники ×1, бонус кількості +0 | Їх змінюють пасивки |
| `pendingLevels` | 0 | Черга, якщо XP вистачило на кілька рівнів одразу |

Коли гравець отримує урон: червоний flash, легка тряска камери, i-frames. Коли HP ≤ 0: секунда анімації смерті, потім `GAME_OVER`.

### 4.2 Enemies

| ID | Назва | Роль | Швидкість, px/с | HP | Урон | XP | На екрані | Радіус |
|---|---|---|---|---|---|---|---|---|
| `gloop` | Gloop | Масовка: повільний, але їх багато | 110 | 10 | 8 | 1 | 100 px | 34 px |
| `scuttler` | Scuttler | Швидкий і крихкий, нападає зграями | 185 | 6 | 5 | 1 | 84 px | 28 px |
| `bruiser` | Bruiser | Повільний «танк», майже не відкидається | 75 | 60 | 15 | 5 | 150 px | 52 px |

**Elite** — модифікатор, який можна накласти на будь-який тип: ×6 HP, ×1.35 розміру і радіуса, ×1.5 урону, +10% швидкості, золотий контур і HP-бар над головою. Завжди залишає скриню і великий кристал.

**Поведінка** (поле `behavior`):
- `chase` — іде прямо на гравця (за замовчуванням).
- `straight` — рухається по прямій у заданому напрямку (для події swarm) і зникає далеко за екраном.
- Пізніше: `ranged` (Lobber, стріляє повільними снарядами), `dash` (Rammer, робить ривок після помітного попередження), `split` (Splitter, після смерті ділиться на двох малих).

**Загальні правила**
- Жоден ворог не швидший за базову швидкість гравця (виняток — ривок із попередженням).
- Вороги м'яко розштовхуються, тож натовп не злипається в одну точку.
- Knockback від влучання затухає приблизно за 0.2 с. Bruiser ігнорує 80% відкидання.
- HP-бари є тільки в elite і боса, у звичайних ворогів це лише візуальний шум.
- Ворога, що відстав далеко за екраном, переносимо на край екрана попереду гравця: від орди не втечеш.

Поля: `type, x, y, hp, maxHp, speed, damage, radius, drawSize, xpValue, isElite, behavior, knockX, knockY, flashTimer, hitTimers, dead`.

### 4.3 Projectiles

Поля: `x, y, vx, vy, radius, damage, pierce, lifetime, knockback, weaponId, hitSet, dead`.

- Летить по прямій і зникає, коли закінчився `pierce` (скільки ворогів може пробити) або `lifetime`.
- `hitSet` пам'ятає, кого снаряд уже вдарив, щоб не влучити в того самого ворога двічі.
- Ворожі снаряди з'являться пізніше: окремий список і контрастний колір.
- Осколки на орбіті, аура і хвиля — не снаряди, а зони урону, якими керує сама зброя (розділ 6).

### 4.4 XP gems

| Номінал | XP | Колір | На екрані | Звідки |
|---|---|---|---|---|
| Малий | 1 | Блакитний | 28 px | Gloop, Scuttler |
| Середній | 5 | Зелений | 36 px | Bruiser |
| Великий | 20 | Фіолетовий | 46 px | Elite, злиття кристалів |

- Кристал лежить там, де загинув ворог. Коли гравець підходить на `pickupRadius`, кристал з прискоренням летить до нього і зараховується при дотику.
- Ліміт — ~300 кристалів. Якщо їх більше, XP нового кристала додається до найдальшого (він стає більшим): об'єктів менше, а XP не губиться.
- Пізніше: рідкісні підбори Gem Magnet (збирає всі кристали) і Heal Orb.

Поля: `x, y, value, radius, isFlying, dead`.

### 4.5 Chests

- Випадає з кожного elite, пізніше й з боса. Світиться золотим, тож її видно здалеку.
- Відкривається при дотику: стан `CHEST`, гра на паузі, ~1 с анімації, картка нагороди, Enter або клік — продовжити.
- Нагорода в прототипі: +1 рівень випадковому предмету гравця, який ще не на максимумі (спершу зброя). Якщо все на максимумі — лікування на 30% HP.
- Пізніше: еволюція зброї (розділ 6) і «багаті» скрині з трьома нагородами.

Поля: `x, y, radius, dead`.

### 4.6 Розміри, спрайти і колізії

Спрайт 182 px на екрані 1920×1080 займає ~17% висоти, тож орда зі 150+ таких ворогів стає суцільною стіною. Тому source завжди 182×182, а розмір на екрані (`drawSize`) кожен тип має свій:

| Сутність | Source | На екрані | Радіус колізії | Діаметр кола від ширини спрайта |
|---|---|---|---|---|
| Player | 182×182 | 128 px | 28 px (hurtbox) | ~45% |
| Gloop | 182×182 | 100 px | 34 px | ~68% |
| Scuttler | 182×182 | 84 px | 28 px | ~67% |
| Bruiser | 182×182 | 150 px | 52 px | ~69% |
| Elite | 182×182 | ×1.35 від базового | ×1.35 | — |
| Снаряд | 64×64 | 32–40 px | 12–16 px | — |
| XP gem | 48×48 | 28–46 px | 16 px | — |
| Скриня | 128×128 | 96 px | 40 px | — |

**Чому так**
- Hurtbox гравця маленький, тому урон зараховується, лише коли спрайти явно перекрилися. Це відчувається чесно.
- Hitbox ворогів більший, тож атаки гравця влучають із запасом. Це приємно.
- Кристали підбираються через великий `pickupRadius`, а не через тіло гравця.
- У debug-режимі всі кола видно поверх спрайтів, і за ними ми налаштовуємо відчуття.

**Procedural placeholders.** На старті гри для кожного типу один раз малюємо спрайт 182×182 у прихований canvas (форма, колір, очі, темний контур) і його білу копію для hit flash. Далі гра використовує їх так само, як PNG. Щоб поставити справжній арт, досить покласти файл у `assets/sprites/` і додати рядок у `data/sprites.js`. Тіні — це еліпс, який малює сама гра.

**Вимоги до арту 182×182** (для художника або AI-генерації):
- PNG з прозорістю, персонаж по центру, з кожного боку ~10–12 px вільного поля.
- Однакова «лінія землі» (низ ніг) в усіх спрайтах. Тіні не малювати.
- Персонаж дивиться вправо, вліво гра віддзеркалить сама.
- Головний тест: силует має читатися, коли спрайт зменшено до ~90 px.
- Анімації (пізніше): горизонтальна стрічка кадрів по 182×182, наприклад 4–6 кадрів ходьби.
- Якщо арт буде pixel art, масштабувати можна лише ×1 або ×0.5, інакше пікселі розмиваються.

### 4.7 Допоміжні ефекти

- **Particles:** іскри при влучанні, вибух при смерті, спалах на Level Up. Ліміт ~500.
- **FloatingText:** числа урону, які піднімаються і зникають за ~0.6 с. Ліміт ~60, можна вимкнути.
- Пізніше: банери подій («A swarm is coming!») і стрілки, що вказують на elite або скриню за екраном.

## 5. Система апгрейдів

**Які бувають картки**
1. Нова зброя — якщо є вільний слот для зброї.
2. +1 рівень зброї, яка вже є (якщо вона не на максимумі).
3. Нова пасивка — якщо є вільний слот для пасивок.
4. +1 рівень пасивки, яка вже є.
5. Запасні, коли нічого іншого не лишилося: Heal (+30% HP), пізніше Gold.

**Ліміти:** зброя — 4 слоти, максимум 5-й рівень. Пасивки — 4 слоти, максимум 5-й рівень (числа в `config.js`). Пасивок 6, а слотів лише 4, тож кожен вибір має вагу.

**Як обираються 3 картки**
1. Зібрати всі доступні варіанти за правилами вище.
2. Призначити ваги: апгрейд зброї, яка вже є, — ×2 (щоб білд поглиблювався), решта — ×1. Ваги зберігаються в `data/`.
3. Випадково витягти 3 різні варіанти з урахуванням ваг.
4. Якщо варіантів менше трьох, додати запасні.

**Черга рівнів.** Якщо великий кристал дав одразу 2+ рівні, екран Level Up з'являється кілька разів поспіль.

**Як поводиться екран Level Up**
- Світ на паузі, таймер забігу стоїть.
- Перші 0.4 с вибір заблоковано, щоб не натиснути випадково.
- Вибір: клавіші 1/2/3, клік мишею або стрілки + Enter.
- Після вибору хвиля відштовхує ворогів у радіусі ~250 px, і гравець 0.5 с невразливий. Так не можна загинути одразу після паузи.

**Пасивки (`data/passives.js`)**

| ID | Назва | За кожен рівень (макс. 5) | На що впливає |
|---|---|---|---|
| `power` | Power | +10% урону | Уся зброя |
| `haste` | Haste | −6% cooldown | Seeker Bolt, Shockwave, частота ударів Heat Aura |
| `reach` | Reach | +10% area | Радіус Heat Aura, орбіта й розмір осколків, радіус Shockwave, розмір снарядів |
| `swiftness` | Swiftness | +8% швидкості руху | Гравець |
| `vitality` | Vitality | +20 max HP (і лікує на 20) | Гравець |
| `magnet` | Magnet | +25% радіуса підбору | Кристали |

Пізніше: Recovery (регенерація), Guard (менше вхідного урону), Echo (+1 снаряд), Insight (+XP), Fortune (удача).

**Фінальні стати зброї** (однакова формула для всієї зброї)
- Урон = урон зброї на її рівні × множник урону гравця.
- Cooldown = cooldown зброї × множник cooldown гравця (не менше 0.1 с).
- Розмір/радіус = значення зброї × множник area гравця.
- Кількість = кількість зброї + бонус кількості гравця.
- Множник від пасивки = 1 + бонус × рівень (наприклад, Power Lv3 = ×1.3). Просто й зрозуміло.

**XP до наступного рівня:** `5 + 8 × (L − 1) + 0.4 × (L − 1)²`, з округленням. Виходить 5 → 13 → 23 → 33 → 43… ~110 на 10-му рівні, ~300 на 20-му. Перші рівні приходять дуже швидко, щоб затягнути, далі повільніше.

**Формат даних.** Кожен предмет має `id`, назву, тип, іконку, `maxLevel`, вагу і список рівнів. Кожен рівень — це опис для картки плюс зміни статів. Картка завжди показує, що саме дасть наступний рівень («Lv 2 → 3: +5 damage»).

## 6. Система зброї

**Архітектура**
- `Weapon` (базовий клас): `id`, `level`, таймер cooldown, `getStats()` (стати рівня з урахуванням множників гравця), `levelUp()`, `update(dt, game)`, `draw(ctx, camera)`.
- Від нього успадковуються 4 типи поведінки:
  - `BoltWeapon` — снаряди летять у найближчих ворогів.
  - `OrbitWeapon` — предмети обертаються навколо гравця.
  - `AuraWeapon` — зона навколо гравця, що б'є з певним інтервалом.
  - `WaveWeapon` — кільце, що розширюється від гравця.
- Нова зброя — це новий запис у `data/weapons.js`. Новий клас потрібен лише тоді, коли з'являється нова поведінка.

**Стати зброї:** `damage, cooldown, amount, speed, area, pierce, lifetime, knockback, hitCooldown`. `hitCooldown` визначає, як часто зона урону може бити того самого ворога.

**Seeker Bolt** — стартова зброя
Цілиться в найближчого ворога в радіусі ~900 px. Якщо ворогів поруч немає, не стріляє і чекає. Коли снарядів кілька, вони летять у N найближчих різних ворогів. Якщо ворогів менше, зайві снаряди розходяться віялом ±10°.

| Рівень | Що дає |
|---|---|
| 1 | 12 урону, cooldown 0.9 с, 1 снаряд, 800 px/с, pierce 1, lifetime 1.4 с |
| 2 | +1 снаряд |
| 3 | +5 урону |
| 4 | −20% cooldown |
| 5 | +1 снаряд, +1 pierce |

**Orbit Shards**
Осколки обертаються на відстані 150 px зі швидкістю 2.5 рад/с. Того самого ворога ця зброя б'є не частіше ніж раз на 0.4 с. Cooldown немає, тож Haste на неї не діє, і це теж частина вибору.

| Рівень | Що дає |
|---|---|
| 1 | 2 осколки, 8 урону |
| 2 | +1 осколок |
| 3 | +4 урону, +15% радіуса орбіти |
| 4 | +1 осколок |
| 5 | +30% швидкості обертання, +4 урону |

**Heat Aura**
Коло радіусом 130 px навколо гравця. Кожні 0.5 с б'є всіх ворогів усередині. Малюється напівпрозорим колом на «землі», під ворогами.

| Рівень | Що дає |
|---|---|
| 1 | 5 урону за удар |
| 2 | +20% радіуса |
| 3 | +3 урону |
| 4 | Удар кожні 0.4 с |
| 5 | +20% радіуса, вороги всередині сповільнюються на 25% |

**Shockwave**
Кожні 3 с від гравця розходиться кільце: до 320 px за 0.35 с. Кожного ворога б'є один раз за хвилю і сильно відкидає, тож дає перепочити.

| Рівень | Що дає |
|---|---|
| 1 | 18 урону |
| 2 | +6 урону |
| 3 | −15% cooldown |
| 4 | +25% радіуса |
| 5 | Друга хвиля через 0.3 с |

**Еволюції** (після прототипу; назви робочі)
Умова: зброя на максимальному рівні і потрібна пасивка є в білді (рівень не важливий). Тоді іконка зброї в HUD світиться, а наступна скриня гарантовано її еволюціонує. Еволюція займає той самий слот.

| Heat Aura | Power | Inferno Mantle | Вороги, що гинуть в аурі, вибухають і ранять сусідів |
| Shockwave | Swiftness | Tremor Stride | Крім звичайних хвиль, ще одна хвиля кожні ~300 px руху гравця |

## 7. Хвилі ворогів

**Spawner** працює від таймера забігу і таблиці `data/waves.js`. Кожен рядок таблиці — це проміжок часу, типи ворогів із вагами, частота спавну (ворогів за секунду), ліміт живих ворогів і множники HP та швидкості.

**Де з'являються вороги.** У випадковій точці на периметрі прямокутника екрана, розширеного на ~120 px. Вороги виходять з-за краю, а не виникають на очах у гравця. Пізніше можна частіше спавнити їх з боку, куди гравець рухається.

**Правила**
- Ліміт живих ворогів у прототипі — 300, щоб не просідала продуктивність. Коли ліміт досягнуто, спавн чекає.
- Ворога, що відстав більш як на ~700 px за край екрана, переносимо на край попереду гравця. Elite при цьому зберігає своє HP.
- Швидкість ворогів росте щонайбільше на +25%, тож навіть без апгрейдів гравець швидший за будь-кого з них.
- HP ворогів росте з часом. Інакше після 5-ї хвилини грати стає надто легко.

**Таймлайн прототипу** (стартові значення для тюнінгу)

| Час | Вороги (частка) | Спавн/с | Макс. живих | HP | Події |
|---|---|---|---|---|---|
| 0:00–1:00 | Gloop 100% | 0.8 → 1.2 | 30 | ×1.0 | — |
| 1:00–2:00 | Gloop 75%, Scuttler 25% | 1.5 | 50 | ×1.1 | 1:30 — elite Gloop |
| 2:00–3:00 | Gloop 60%, Scuttler 40% | 2.0 | 70 | ×1.2 | 2:30 — swarm зі Scuttler |
| 3:00–5:00 | + Bruiser 10% | 2.5–3.0 | 100 | ×1.35 | 3:00 — elite; 4:30 — ring |
| 5:00–7:00 | Bruiser 20% | 3.5–4.0 | 140 | ×1.6 | 5:00 — elite; 6:00 — swarm |
| 7:00–10:00 | Усі типи | 4.5–6.0 | 200 | ×2.0 | 7:30 — 2 elites; 9:00 — ring |
| 10:00+ | Усі типи | +0.4/с щохвилини | до 300 | +20% щохвилини | Elite щохвилини; пізніше бос на 10:00 |

**Події**
- **Elite.** Один посилений ворог. Коли з'являється, показуємо короткий банер, а пізніше ще й стрілку, що на нього вказує.
- **Swarm.** 20–40 Scuttler-ів пробігають через екран по прямій з одного боку. Треба відійти з їхнього шляху.
- **Ring.** Одразу за краєм екрана з'являється кільце ворогів (еліпс за пропорціями екрана, щоб вони підходили з усіх боків одночасно) і стискається. Треба прорватися назовні.
- За ~2 с до swarm і ring з'являється банер-попередження: напружено, але чесно.

Після 10:00 гра безкінечна: складність росте, доки орда не переможе. Результат забігу — час виживання, а рівень і кількість вбивств показуємо в статистиці.

| Вороги | Теплі й темні: червоний, помаранчевий, брунатний |
| Elite і скрині | Золотий |
| Атаки гравця | Яскраво-жовтий або білий |

**Juice (відчуття від гри)**
- Влучання: ворог на 0.08 с спалахує білим, відлітає назад, з'являється число урону.
- Смерть ворога: «лопається» (змінюється масштаб), розлітаються частинки, падає кристал.
- Підбір кристала: кристал прискорено летить до гравця, на гравцеві маленький спалах.
- Level Up: спалах і хвиля, що відштовхує ворогів.
- Урон гравцю: червоний flash, тряска камери 0.1–0.15 с, мигання, поки діє невразливість.
- Під час руху спрайти трохи «дихають» і похитуються, тож навіть статичні placeholders виглядають живими.
- Пізніше: звук на кожну дію (WebAudio).

**Шрифт** — системний, нічого не завантажуємо, тож працює офлайн. Пізніше можна підключити свій.

Кожен крок маленький, його легко перевірити, а в кінці гра працює і зберігається окремим комітом. Для туторіалу це зручно: один крок — один урок.

## 10. Ризики

| Ризик | Як закриваємо |
|---|---|
| Спрайти 182 px на 1080p перетворюють орду на стіну | Source 182, а на екрані 84–150 px через `drawSize`. Великі тільки elite і бос |
| Фіч стає дедалі більше раніше, ніж петля почне затягувати | Спершу Milestone B–C з однією зброєю. Нові фічі — лише після плейтесту |
| Баланс «на око» | Усі числа в `data/`, debug-клавіші, чекліст плейтесту |
| Продуктивність при 300+ об'єктах | Ліміти, малюємо лише видиме, spatial grid, кеш спрайтів; object pooling за потреби |
| Смерті здаються несправедливими | Малий hurtbox, i-frames, поштовх після Level Up, вороги повільніші за гравця, попередження перед подіями |
| Гра схожа на якусь конкретну існуючу | Власні назви, свої варіації механік, procedural арт; перевірка назви перед публікацією |
