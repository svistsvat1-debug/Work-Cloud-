# Заявки з сайту → CRM + Telegram + лист клієнту

Один Google Apps Script робить усе з п.1 плану:

| Подія | Що відбувається |
|---|---|
| Клієнт заповнює форму на сайті | Рядок у Google Таблиці-CRM: статус «Новий», тип запиту (Сайт / Автоматизація / AI / Інше), мова |
| — одразу ж | Тобі в Telegram **і листом на пошту**: ім'я, контакт, тип, текст, посилання на CRM (у листі reply_to = клієнт, відповідаєш прямо з Gmail) |
| — якщо клієнт залишив email | Йому лист-підтвердження його мовою (UA / EN / PL) з твого Gmail |
| Щодня о 10:00 | Нагадування в Telegram про ліди «Новий» > 1 дня і «В роботі» без руху > 3 днів |
| Щопонеділка о 9:00 | Тижневий звіт: скільки заявок, яких типів, скільки в кожному статусі |

Вартість: 0 (Google-акаунт + Telegram-бот). Код: `Code.gs`.

## Налаштування (~15 хвилин, один раз)

**1. Таблиця.** У Google-акаунті, на який мають приходити заявки, створи нову Google Таблицю, наприклад «Flowbase CRM».

**2. Скрипт.** У таблиці: *Розширення → Apps Script*. Видали вміст `Code.gs` у редакторі, встав увесь вміст файлу `Code.gs` з цієї папки, збережи.

**3. Telegram-бот для сповіщень.**
- У Telegram відкрий @BotFather → `/newbot` → придумай назву (наприклад «Flowbase Leads») → отримаєш **токен**.
- Напиши своєму новому боту будь-яке повідомлення.
- Відкрий у браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайди `"chat":{"id": ...}` — це **chat id**.
- Окремий бот для сповіщень краще, ніж твій автовідповідач: не заважатиме його роботі.

**4. Секрети.** В Apps Script: *Project Settings (шестерня) → Script properties → Add*:

| Property | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен з кроку 3 |
| `TELEGRAM_CHAT_ID` | chat id з кроку 3 |
| `REPLY_WITHIN_HOURS` | необов'язково. Наприклад `24` → у листі буде «відповімо протягом 24 год». Без нього — «найближчим часом». [MISSING] реальний строк, який ти готовий тримати |
| `OWNER_EMAIL` | необов'язково. Пошта, куди слати заявки тобі. Без нього заявки йдуть на пошту, якою ти створив скрипт |

**5. Запуск setup.** У редакторі вибери функцію `setup` → *Run*. Google попросить дозволи (таблиця, пошта, зовнішні запити, тригери). Якщо побачиш «Google hasn't verified this app» → *Advanced → Go to … (unsafe)* — це твій власний скрипт. Потім так само запусти `testTelegram` — має прийти повідомлення.

**6. Публікація.** *Deploy → New deployment → тип Web app*:
- Execute as: **Me**
- Who has access: **Anyone**

Скопіюй URL, що закінчується на `/exec`.

**7. Сайт.** Встав цей URL у `site/assets/js/config.js` → `formEndpoint`. Готово — надішли тестову заявку з сайту.

## Як працювати щодня

- Статус міняєш у колонці «Статус» (випадаючий список). Дата зміни ставиться сама — від неї рахуються нагадування.
- Нотатки по ліду — в колонці «Нотатки».
- Якщо міняєш код: *Deploy → Manage deployments → ✏️ → Version: New version → Deploy*. URL залишається тим самим.

## Обмеження, про які варто знати

- Безкоштовний Gmail дозволяє близько 100 листів на день через скрипти. На одну заявку йде 2 листи (тобі + підтвердження клієнту), тобто вистачає приблизно на 50 заявок на день — з запасом.
- Захист від спаму: приховане поле у формі, не більше 30 заявок за 10 хв загалом (захист від флуду CRM і Telegram), не більше 1 листа на ту саму адресу за 6 год і 20 листів-підтверджень на годину.
- Тип запиту визначається за ключовими словами — це підказка, а не точна класифікація. Виправляй вручну, якщо треба.
