# Edge Journal — журнал бінарних опціонів

Особистий торговий журнал для бінарних опціонів на валютних парах. Одна програма (`public/index.html`), яка працює в трьох місцях:

| Де | Де лежать дані | Для чого |
|---|---|---|
| **Cloudflare Worker** (основний варіант) | D1 (угоди) + R2 (скріни), вхід за паролем | Одна база для телефона й комп'ютера, графік угоди з котирувань |
| Claude-артефакт | приватне сховище артефакту | Тимчасовий варіант до запуску Cloudflare |
| Файл у браузері | IndexedDB цього браузера | Офлайн, без синхронізації |

## Як заносити угоду

1. Скопіюй скрін графіка і натисни **Ctrl+V** на сторінці — відкриється нова угода зі скріном. **N** — нова угода без скріна.
2. Валютна пара (кнопки останніх пар), ↑ Вгору / ↓ Вниз, стратегія, ставка, виплата %, експірація, результат: Плюс / Мінус / Повернення / Ще йде, рух у пунктах (на Cloudflare — кнопка «авто»).
3. Аналіз, що пішло не за планом, помилки, емоції. **Ctrl+Enter** — зберегти.

У картці угоди:
- **«Відкрити в TradingView»** — пара на хвилинному графіку. Щоб перейти до угоди: на комп’ютері Alt+G і встав скопійовані дату й час; на телефоні — під графіком кнопка періоду (1Д, 5Д…) → «Перейти до…». Часовий пояс графіка в TradingView має збігатися з поясом журналу.
- На Cloudflare — **графік угоди** з хвилинних котирувань: угода позначена прямокутником від входу (час і ціна) до експірації (час і ціна), зелений — ціна пішла у твій бік, червоний — проти; рівень входу, рух у пунктах і кнопка записати його в угоду.

## Запуск на Cloudflare

Код: `wrangler.toml`, `src/worker.js` (API), `public/` (сторінка). Ключі й секрети не потрібні: база D1 `edge-journal` і бакет R2 `edge-journal-shots` створюються автоматично при першому деплої, таблиці — при першому запиті, котирування беруться з Dukascopy без ключа, пароль створюється на самому сайті.

1. **dash.cloudflare.com → Workers & Pages → Create → Import a repository**, підключи GitHub і обери `svistsvat1-debug/work-cloud-`.
2. Project name: `edge-journal`. Root directory (Path): `trading-journal`. Решту полів не чіпай (Deploy command — `npx wrangler deploy`). Гілка — `workproces`.
3. **Deploy.** Якщо Cloudflare попросить увімкнути R2 — погодься.
4. Одразу відкрий адресу Worker (`https://edge-journal.<твій-піддомен>.workers.dev`) і **створи пароль** — його створює той, хто першим відкриє свіжий сайт.
5. Перенос угод зі старого журналу: там **Налаштування → Експорт JSON**, тут **Налаштування → Імпорт JSON** (скріни переносяться теж).

Після цього кожен push у гілку автоматично оновлює сайт.

- **Змінити пароль:** Налаштування → Дані → «Змінити пароль» (інші пристрої вийдуть).
- **Забув пароль:** Cloudflare → Storage & Databases → D1 → `edge-journal` → Console → `DELETE FROM auth;`, потім відкрий сайт і створи новий.
- **Необов’язкові секрети:** `JOURNAL_PASSWORD` (замінює пароль з сайту), `TWELVE_DATA_KEY` (запасне джерело котирувань).

Локально: `npm ci`, потім `npx wrangler dev`. Для офлайн-перевірки котирувань у `.dev.vars` можна вказати `DUKASCOPY_ROOT=` на локальний сервер з тим самим форматом відповіді.

## API (`src/worker.js`)

Усе, крім `/api/setup` і `/api/login`, вимагає сесійної cookie (HttpOnly, Secure, SameSite=Strict, 180 днів). Пароль зберігається як PBKDF2-SHA256 із сіллю; ключ підпису сесій виводиться з нього, тож зміна пароля виходить з усіх пристроїв. 10 невдалих спроб з однієї IP — блок на 15 хвилин. Запити з чужого Origin відхиляються.

| Метод | Шлях | Що робить |
|---|---|---|
| POST | `/api/setup` | створити пароль (лише поки його немає) |
| POST | `/api/login`, `/api/logout` | вхід / вихід |
| POST | `/api/password` | змінити пароль |
| GET | `/api/me` | чи є сесія, чи підключені котирування |
| GET | `/api/data` | усі угоди й налаштування |
| PUT / DELETE | `/api/trades/:id` | зберегти / видалити угоду |
| PUT | `/api/settings` | зберегти налаштування |
| POST / GET / DELETE | `/api/images[/:id]` | скріни в R2 (PNG, JPEG, WebP, GIF, до 15 МБ) |
| GET | `/api/candles?pair=EUR/USD&from=ms&to=ms` | хвилинні свічки BID з Dukascopy (UTC; Twelve Data — запасний варіант); минулі відрізки кешуються в D1 |

## Що рахує

- Прибуток угоди: плюс = ставка × виплата %, мінус = −ставка, повернення = 0.
- Час закриття = час входу + експірація (10:16 + 2 хв → 10:18). Час угод — у часовому поясі з налаштувань (за замовчуванням — пояс пристрою).
- Рух у пунктах вводиться як відстань; знак — з результату (плюс — у твій бік). Авто-пункти: ціна на вході й на експірації з хвилинних свічок (на межі хвилини — open, всередині хвилини — найближчий край); пункт = 0,0001, для пар з JPY — 0,01.
- Вінрейт = плюсові ÷ (плюсові + мінусові). Потрібний вінрейт = 1 ÷ (1 + виплата); при 85% — 54,1%.
- Profit factor, ROI оборота, середня угода й ставка, просідання, серії, ціна помилок, «підняв ставку після мінуса», дні, години, пари, експірації, емоції, розмір ставки.

## Обмеження

- OTC-пари — котирування самого брокера; ні графіка, ні авто-пунктів для них немає.
- Котирування постачальника можуть трохи відрізнятись від брокерських; журнал попереджає, якщо напрям руху не збігається з результатом у брокера.
- Dukascopy — безкоштовне, але неофіційне джерело (той самий ендпоінт, що в бібліотеці dukascopy-node). Якщо воно зміниться, додай `TWELVE_DATA_KEY` — журнал перейде на Twelve Data.
- Хвилинні свічки дають точність до хвилини; експірації в секундах (30 с) рахуються наближено.
